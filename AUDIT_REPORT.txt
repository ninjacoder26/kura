#1  [Security/Critical] Exposed Supabase credentials in .env file
    File: .env, lines 2-3
    The .env file contains real Supabase URL and anon key values. While
    .gitignore lists .env, the file exists locally with real credentials.
    If this was ever committed, the project URL is exposed.
    Severity: Critical

#2  [Security/High] JavaScript URI XSS via user-submitted post links
    File: src/components/post/PostCard.tsx, line 163
    File: src/app/post/[id]/page.tsx, line 145
    Post URLs are rendered as <a href={post.url}> directly from user input.
    A user could submit javascript:alert(document.cookie) as a URL. React
    does NOT sanitize href attributes on <a> tags against javascript: URIs.
    Severity: High

#3  [Security/High] Open redirect potential in auth callback
    File: src/app/auth/callback/route.ts, lines 7, 24
    The next search parameter is used to construct a redirect URL without
    validation. A crafted next value with special characters or newlines
    could potentially manipulate the redirect. Should validate as relative
    path starting with /.
    Severity: High

#4  [Security/Medium] Missing authorization re-verification on post edit
    File: src/app/post/[id]/edit/page.tsx, lines 35, 44-54
    The ownership check is only done on page load. The form submission does
    not re-verify ownership. While Supabase RLS should prevent unauthorized
    updates, the frontend has a TOCTOU gap.
    Severity: Medium

#5  [Security/Medium] Image upload lacks MIME type validation
    File: src/app/submit/page.tsx, lines 64-72
    Only file size is validated (20MB). No MIME type or file extension
    validation. A user could upload malicious SVG files or non-image files.
    The HTML accept="image/*" is just a browser hint, not enforced.
    Severity: Medium

#6  [Security/Medium] No rate limiting on authentication endpoints
    Files: Login, signup, forgot-password pages
    No client-side or server-side rate limiting on login attempts, signup
    attempts, or password reset requests. Vulnerable to brute-force attacks.
    Severity: Medium

#7  [Security/Medium] Post deletion allows hard-delete via API
    File: supabase/migrations/001_initial_schema.sql, line 269
    File: src/components/post/PostCard.tsx, line 107
    The RLS policy allows DELETE operations, but the UI only soft-deletes.
    A user could bypass the UI and hard-delete posts via the API.
    Severity: Medium

#8  [Security/Medium] No is_locked enforcement on comment creation
    File: src/app/post/[id]/page.tsx, lines 104-113
    Posts have an is_locked boolean field, but the comment form and backend
    don't check it before allowing comments. Locked posts can still receive
    comments.
    Severity: Medium

#9  [Security/Low] Missing username uniqueness validation during OAuth signup
    File: src/app/auth/callback/route.ts, line 19
    When creating a profile for OAuth users, the username is derived from
    the email prefix. If two users have the same email prefix, the database
    insert will fail with a constraint violation, but the error is not
    handled, potentially leaving the user without a profile.
    Severity: Low

#10 [Security/Low] Search ilike filter treats user input as LIKE pattern
    File: src/app/search/page.tsx, line 34
    The or filter uses ilike with user input wrapped in %. Characters like
    % and _ in the search query would be treated as SQL LIKE wildcards,
    potentially returning unintended results.
    Severity: Low

#11 [Bug/Critical] Score double-counted in post detail page
    File: src/app/post/[id]/page.tsx, lines 40-47
    Line 40 sets setScore(postData.upvotes - postData.downvotes). The
    database triggers already include the user's vote in these counts.
    Then line 46 adds +1 or -1 again. This double-counts the user's own
    vote, showing an incorrect score.
    Severity: Critical

#12 [Bug/High] "Hot" sort is identical to "Top" sort
    File: src/app/page.tsx, lines 54-56
    Both sort === 'top' and the else (hot) branch use
    query.order('upvotes', { ascending: false }). The "Hot" sort should
    factor in both votes and recency (time-decay), but it behaves
    identically to "Top".
    Severity: High

#13 [Bug/High] Comment count not decremented on soft-delete
    File: supabase/migrations/001_initial_schema.sql, lines 468-484
    The handle_comment_count trigger only fires on INSERT and DELETE (hard
    delete). Since comments are soft-deleted (is_removed = true), the
    comment_count on posts never decrements when comments are removed.
    Severity: High

#14 [Bug/High] Profile post_count and comment_count never updated
    File: supabase/migrations/001_initial_schema.sql
    The profiles table has post_count and comment_count columns, but there
    are no database triggers to increment/decrement these when users create
    or delete posts/comments. The counts will always remain at 0.
    Severity: High

#15 [Bug/Medium] Post submit button is outside <form> element
    File: src/app/submit/page.tsx, lines 157-188
    The submit button (line 186) is outside the <form> element. While the
    button has onClick={handleSubmit}, pressing Enter in form fields
    triggers the form's onSubmit but the button's disabled state isn't
    reflected.
    Severity: Medium

#16 [Bug/Medium] OAuth callback profile creation may fail silently
    File: src/app/auth/callback/route.ts, lines 16-22
    If the database trigger handle_new_user already created the profile,
    the callback's insert will fail due to the unique constraint. The
    error is not caught or handled, potentially leaving the user stuck.
    Severity: Medium

#17 [Bug/Medium] No updated_at auto-update trigger
    File: supabase/migrations/001_initial_schema.sql
    Multiple tables have updated_at columns but there is no trigger to
    automatically update the timestamp when rows are modified. The
    updated_at value will remain at the initial creation time.
    Severity: Medium

#18 [Bug/Medium] Theme flash on page load
    File: src/components/providers/ThemeProvider.tsx, lines 19-22
    Theme is read from localStorage in a useEffect (client-side only),
    meaning the initial server render always uses the light theme. Users
    will see a flash of light theme before dark theme is applied.
    Severity: Medium

#19 [Bug/Low] Voting race condition with optimistic updates
    Files: PostCard.tsx, post/[id]/page.tsx, CommentThread.tsx
    Vote handlers update local state optimistically before the API call
    completes. If the API call fails, the UI state is already changed
    and there is no rollback mechanism.
    Severity: Low

#20 [Bug/Low] clipboard.writeText failure not handled
    Files: PostCard.tsx line 119, post/[id]/page.tsx line 119
    navigator.clipboard.writeText(url) can fail in insecure contexts
    (HTTP) or when clipboard permission is denied. No error handling
    or fallback is provided.
    Severity: Low
